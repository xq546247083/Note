# Qdrant学习笔记

## Qdrant概述

    1、Qdrant
        Qdrant 是一个向量相似度搜索引擎，它提供了一个生产就绪的服务，带有方便的 API 来存储、搜索和管理带有附加负载（payload）的点（即向量）。您可以将这些负载视为额外的信息，它们可以帮助您精准定位搜索，并接收可以提供给用户的有用信息。
    2、向量数据库
        向量数据库是一种旨在高效存储和查询高维向量的数据库。
    3、向量的距离度量
        1、余弦相似度是一种衡量两个向量相似程度的方法。简单来说，它反映了向量是否具有相同的方向（相似）还是南辕北辙。余弦相似度经常用于文本表示，以比较两个文档或句子的相似度。余弦相似度的输出范围从 -1 到 1，其中 -1 表示两个向量完全不同，1 表示相似度最大。
        2、点积相似度度量是衡量两个向量相似程度的另一种方法。与余弦相似度不同，它还考虑了向量的长度。这可能很重要，例如，当您的文档向量表示是基于词频（词频）构建的时候。点积相似度是通过将两个向量中的对应值相乘，然后将这些乘积相加来计算的。和越大，说明两个向量越相似。如果对向量进行归一化（使其内部数值之和为 1），点积相似度就会变成余弦相似度。
        3、欧氏距离是测量空间中两点之间距离的一种方法，类似于我们测量地图上两地之间的距离。它的计算方式是求两点坐标之差的平方和的平方根。这种距离度量也常用于机器学习中，用以衡量两个向量的相似或不相似程度。
    4、基本元素
        1、集合（Collections）
            集合是您可以在其中进行搜索的点（带有负载的向量）的命名集合。同一集合内每个点的向量必须具有相同的维度，并使用相同的度量进行比较。命名向量（Named vectors）可用于在单个点中包含多个向量，每个向量可以具有各自的维度和度量要求。
        2、距离度量（Distance Metrics）
            这些度量用于衡量向量之间的相似度，且必须在创建集合的同时进行选择。度量的选择取决于获取向量的方式，尤其是用于对新查询进行编码的神经网络。
        3、点（Points）
            点是 Qdrant 操作的核心实体，它们由一个向量、一个可选 ID 以及负载（payload）组成。
                1、id：向量的唯一标识符。
                2、向量（Vector）：数据的高维表示，例如图像、声音、文档、视频等。
                3、负载（Payload）：负载是一个 JSON 对象，包含您可以添加到向量中的附加数据。
    5、存储（Storage）
        Qdrant 在磁盘上持久化数据，并且允许您选择有多少数据也驻留在内存中：pinned 用于将热数据完全保留在 RAM 中，cached 用于热磁盘缓存，或者 cold 用于在大型数据集上节省 RAM。

## 数据管理

### 点

    点是 Qdrant 操作的核心实体。一个点是一个记录，由一个向量和一个可选的负载（payload）组成。
    1、点ID
        支持使用64位无符号整数和UUID作为点的标识符
    2、向量
        Qdrant中的每个点可以有【一个或多个】向量。向量是 Qdrant 架构的核心组件。Qdrant 依赖不同类型的向量来提供不同类型的数据探索和搜索。以下是支持的向量类型列表：
        1、稠密向量
            常规向量，由大多数嵌入模型生成。
        2、稀疏向量
            没有固定长度，但只有少数非零元素的向量。适用于精确令牌匹配和协同过滤推荐。
        3、多向量（MultiVectors）
            长度固定但高度可变的数字矩阵。通常从 ColBERT 等后期交互模型中获得。
    3、命名向量
        可以将【多种类型】的向量附加到单个点。搜索的时候，选择要搜索的命名向量。

### 向量

    向量（或嵌入）是 Qdrant 向量搜索引擎的核心概念。向量定义了向量空间中对象之间的相似性。
    1、稠密向量
        这是最常见的向量类型。它是一个简单的数字列表，具有固定长度，列表中每个元素都是浮点数。
    2、稀疏向量
        稀疏向量是一种特殊类型的向量。从数学上讲，它们与稠密向量相同，但包含许多零，因此以特殊格式存储。
    3、命名向量
        您可以在同一个数据点中存储不同大小和类型的多个向量。
        1、要为每个点存储不同的向量，您需要在集合中创建单独的命名向量空间。
        2、在存储的时候，指定各个命名向量的值。
        3、在搜索的时候，指定一个命名向量搜索。

### 负载

    Qdrant 的重要特性之一是能够与向量一起存储附加信息。在 Qdrant 术语中，这些信息被称为 payload。Qdrant 允许您存储任何可以使用 JSON 表示的信息。
    1、Payload类型
        1、整数
        2、浮点数
        3、布尔值
        4、关键字
        5、地理位置
            geo
        6、日期时间
            RFC 3339 格式的日期和时间
        7、UUID
    2、过滤条件
        1、id
            通过id，直接锁定
        2、MatchKeyword
            过滤关键字
    3、更新数据
        1、SetPayloadAsync
            对传入键的负载更新，没传入键的负载不变
        2、OverwritePayloadAsync
            覆盖数据库的负载
        3、ClearPayloadAsync
            清空所有负载
        4、DeletePayloadAsync
            删除指定键的负载
    4、索引
        为了在使用过滤器时进行更高效的搜索，Qdrant 允许您通过指定期望的字段名称 and 类型来为 payload 字段创建索引。关键字：CreatePayloadIndexAsync
    5、分面计数
        分面 (Faceting) 是一种特殊的计数技术，类似于 SQL 中的 GROUP BY 和 COUNT(*) 命令，可用于各种目的：
            1、了解一个 payload 键存在哪些唯一值。
            2、了解包含每个唯一值的点 (points) 的数量。
            3、了解匹配特定值时过滤器的限制性会有多强。
        关键字：FacetAsync

### 集合

    集合是点的命名集（带有有效载荷的向量），您可以在其中进行搜索。同一集合中每个点的向量必须具有相同的维度，并由单一度量进行比较。每个集合都使用自己的一组参数来控制集合优化、索引构建和清理。
    1、距离度量用于衡量向量之间的相似性。
        1、点积：Dot
        2、余弦相似度：Cosine
        3、欧几里得距离：Euclid

        5、payload.memory

        6、quantization_config

            CreateVectorNameAsync

    8、集合别名

### 存储

    一个集合（collection）中的所有数据均划分为多个数据段（segment）。每个数据段都拥有独立的向量和 payload 存储以及索引。
    1、向量存储
        Qdrant 始终将向量存储在磁盘上的内存映射文件中。根据应用程序的需求，您可以配置内存层级，以控制是否同时将向量加载到 RAM 中来实现更快地访问。
        1、cached - Qdrant 在启动时会将文件预加载到磁盘缓存中，因此首次请求速度很快。这是默认设置；它需要足够的 RAM 来容纳向量。
        2、cold - Qdrant 不会预加载文件到 RAM 中。首次请求可能会较慢，因为 Qdrant 需要从磁盘读取，但操作系统会在访问时对页面进行缓存。
    2、Payload存储
        Qdrant 支持两种用于 payload 的内存层级：cached 和 cold（默认值）。无论使用哪个层级，均使用磁盘和 Gridstore 进行持久化。

### 索引

    Qdrant 的一个关键特性是有效结合了向量索引和传统索引。这一点至关重要，因为要使向量搜索与过滤器有效协同工作，仅有向量索引是不够的。简而言之，向量索引加速向量搜索，而 payload 索引加速过滤。
    1、Payload索引
        1、普通索引
            Qdrant 中的 Payload 索引类似于传统面向文档数据库中的索引。此索引针对特定字段和类型构建，用于根据相应的过滤条件快速请求点。该索引还用于准确估计过滤器基数，这有助于 查询规划 选择搜索策略。创建索引 CreatePayloadIndexAsync
        2、租户索引
            相对于普通索引，这个索引会把相同租户的数据在磁盘上放置得更近，这将减少搜索期间的磁盘读取次数。
        3、主索引
            相对于普通索引，这个索引会按照大小顺序排序，优化范围查询。所以只支持integer，float，datetime。
    2、全文索引
        全文索引使字符串 payload 字段中的单词可搜索。索引配置控制文本的处理方式：如何对其进行分词（拆分为可搜索的 标记）、匹配是否不区分大小写，以及是否应用词干提取或停用词。您可以使用它来：
            1、过滤 包含其文本中的单词和短语的点。
            2、使用 BM25 对点进行排名，根据其文本与查询的相关性。
        1、BM25 评分
            启用评分后，全文索引可以使用 BM25 排名函数根据文本与查询的相关性对点进行排名。要启用评分，请在创建索引时将 scoring 类型设置为 bm25
        2、分词器
            分词器是用于将文本拆分成称为标记的更小单元的算法，这些标记随后在全文索引中进行索引和搜索。
        3、词干提取器
            词干提取器 是一种用于文本处理的算法，用于将单词还原为它们的词根或基本形式，
        4、短语匹配
            就是多几个单词组成的短语，进行匹配。PhraseMatching 
    3、向量索引
        向量索引是通过特定数学模型在向量上构建的数据结构。通过向量索引，我们可以高效地查询与目标向量相似的多个向量。Qdrant 目前仅使用 HNSW 作为稠密向量索引。
        1、HNSW
            HNSW（Hierarchical Navigable Small World Graph，分层可导航小世界图）是一种基于图的索引算法。它根据一定的规则为图像构建多层导航结构。在这种结构中，上层更稀疏，节点之间的距离更远。下层更密集，节点之间的距离更近。搜索从最上层开始，在该层中找到最接近目标的节点，然后进入下一层开始另一次搜索。经过多次迭代，它可以快速接近目标位置。
        2、可过滤HNSW索引
            就是可以向量索引，同时还负载索引。Qdrant通过基于索引的Payload值扩展HNSW图，为其添加额外的边来解决此问题。
        3、禁用为Payload字段创建额外边
            因为部分负载索引可能只会单独索引，如果再聚合到HNSW的边中，就没有意义。EnableHnsw
        4、重建HNSW索引
    4、稀疏向量索引
        Qdrant 中的稀疏向量使用一种特殊的数据结构进行索引，该结构针对具有高比例零值的向量进行了优化。
        1、IDF修改器
            对稀疏向量点积计算的时候，对稀有词进行加权。

### 量化

    量化是 Qdrant 中一项可选功能，可实现高维向量的高效存储和搜索。
        1、通过将原始向量转换为新的表示形式，量化在压缩数据的同时，能保持向量之间接近原始的相对距离。
        2、不同的量化方法具有不同的机制和权衡。
        3、量化主要用于减少高维向量空间的内存占用并加速搜索过程。
    1、Qdrant 支持四种量化方法
        1、TurboQuant
            支持 4 倍到 32 倍压缩，在大多数嵌入模型中具有强大的召回率。
        2、标量量化
            将每个向量分量从 32 位浮点数压缩为 8 位整数，实现 4 倍压缩，同时最大限度地减少精度损失。
        3、二进制量化
            将每个向量分量减少到一到两位，最高可达 32 倍压缩。最适合高维、中心化向量分布。
        4、乘积量化
            当最小化内存是首要任务时，可实现高达 64 倍的压缩。

### 多租户

    每个租户的数据必须保持隔离：当租户搜索时，他们应该只看到自己的数据。
    1、按载荷分区
        要在共享集合中分区数据，请为每个点添加一个标识租户的载荷字段。然后，您可以按此字段进行过滤，以确保每个租户只看到自己的数据。Qdrant 会组织存储结构，将同一租户的向量共置在一起，这可以通过在查询期间利用顺序读取来显著提高性能。
    2、定义分片
        可以把不同租户隔离到不同的分片中。
    3、分层多租户

### 性能优化

    1、批量上传
    2、多线程并行化
    3、创建包含多个分片的 Collection
        在 Qdrant 中，每个 collection 都会被切分为多个分片（shard）。默认情况下，一个 collection 只有一个分片，但在创建 collection 时可以指定更多。通过创建多个分片，可以并行上传大型数据集。
    4、在写入数据前创建 Payload 索引

## 搜索

### 相似性搜索

    搜索最近的向量是许多表示学习应用的核心。现代神经网络经过训练，可以将对象转换为向量，使现实世界中相近的对象在向量空间中也表现为相近。例如，这可以是含义相似的文本、视觉上相似的图片或相同风格的歌曲。
    1、度量算法
        点积、余弦相似度、欧氏距离、曼哈顿距离
    2、搜索API
        1、QueryAsync
        2、按分数过滤结果
        3、设置结果中的负载和向量
            with_vectors、with_payload
    3、批量搜索 API
    4、按ID查询
    5、分页
        offset、limit
    6、分组API
        QueryGroupsAsync
    7、随机采样
        随机查询

### 筛选

    使用 Qdrant，您可以在搜索或检索点时设置条件。ScrollAsync
    1、过滤子句
        1、必须 (Must)
            MatchKeyword("city", "London") & MatchKeyword("color", "red")
        2、应该 (Should)
            MatchKeyword("city", "London") | MatchKeyword("color", "red")
        3、不能 (Must Not)
            !(MatchKeyword("city", "London") & MatchKeyword("color", "red"))
        4、子句组合
    2、过滤条件
        1、精确匹配条件
            1、匹配 (Match)
                最简单的条件是检查存储值是否等于给定值的条件。如果存储了多个值，则其中至少一个应与条件匹配。您可以将其应用于关键字、整数、布尔值和UUID有效载荷。MatchKeyword、Match
            2、匹配任意(Match Any)
                Match("color", ["black", "yellow"]);
            3、匹配排除 (Match Except)
                MatchExcept("color", ["black", "yellow"]);
            4、前缀匹配
            5、子字符串匹配
                这个不应该使用，很吃性能。MatchSubstring("url", "qdrant.tech/");
        2、文本匹配
            最小单位就是分词下来的词语。按照这个词语来匹配。
            1、全文匹配
                MatchText("description", "good cheap");
            2、任意全文匹配
                文本字段只包含一个查询术语，也被视为匹配。MatchTextAny("description", "good cheap");
            3、短语匹配
        3、范围
            range条件设置了存储有效载荷值的可能值范围。gt、gte、lt、lte
        4、地理位置
            1、地理边界框
                GeoBoundingBox("location", 52.520711, 13.403683, 52.495862, 13.455868);
            2、地理半径
                GeoRadius("location", 52.520711, 13.403683, 1000.0f);
            3、地理多边形
                GeoPolygon
        5、嵌套键
            Json对线的嵌套对象的字段过滤
        6、值计数
            除了直接值比较之外，还可以按值的数量进行过滤。ValuesCount("comments", new ValuesCount { Gt = 2 });
        7、是否为空 (Is Empty)
            IsEmpty("reports");
        8、是否为 Null (Is Null)
            IsNull("reports");
        9、具有ID
            HasId
        10、具有向量

            过滤切片

### 混合查询

    你可以通过多种方式搜索相同的数据：使用用于语义搜索的稠密向量，使用来自 SPLADE++ 等学习模型的稀疏向量，以及在具有 全文索引 的文本负载（payload）字段上进行 BM25 全文搜索。通常，通过组合这些查询，或者通过多阶段搜索（例如，先通过快速查询获取候选结果，再用更准确的查询进行重新评分），可以获得最佳结果。
    1、倒排排名融合 (Reciprocal Rank Fusion, RRF)
    2、基于分布的分数融合 (Distribution-Based Score Fusion, DBSF)
